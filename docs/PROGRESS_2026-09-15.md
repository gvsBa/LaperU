## Pekerjaan yang benar-benar dilanjutkan

1. Menyiapkan runner database QA terisolasi dari binary XAMPP yang sudah terpasang, tanpa mengubah service/data XAMPP pengguna. Password, port, direktori data, dan database dibuat khusus setiap run.
2. Menjalankan migration serta seed dua kali per run; berhasil membuat dan menggunakan schema database nyata.
3. Menambahkan suite integrasi API lintas Guest, Customer, UMKM, dan Admin dengan akun dummy unik; SQL tidak dimock. HTTP dijalankan melalui Supertest, bukan browser.
4. Memperbaiki bug `req.query` Express 5 yang menyebabkan pencarian dan daftar pengajuan mengembalikan HTTP 500. Tes reproduksi gagal sebelum perbaikan dan lulus sesudahnya.
5. Memisahkan kegagalan database dari error JWT. Error SQL tidak lagi salah dilaporkan sebagai 401 sesi kedaluwarsa.
6. Memperbaiki rotasi refresh token: conditional claim dalam transaksi, rollback penuh, serta maksimal tiga percobaan untuk deadlock InnoDB. Satu refresh token tidak dapat menghasilkan dua rotasi sukses bersamaan dalam skenario yang diuji.
7. Menambahkan `profileId/submissionId` pada response pengajuan tanpa mengubah makna `id` lama, menambahkan `categoryId` untuk form edit warung, serta memvalidasi tujuh hari operasional unik dan jam wajib pada hari buka.
8. Memperbaiki entrypoint hasil build menjadi `dist/src/server.js`, mengecualikan hasil build dari penemuan tes, dan mencakup Backend dalam konfigurasi ESLint.
9. Menyiapkan handoff teknis SDD dan petunjuk menjalankan ulang pengujian untuk SA, FE, dan QA.

### Cakupan 16 skenario integrasi

- Koneksi database, metadata hasil seed, dan login Admin QA.
- Registrasi Customer, email duplikat, input invalid.
- Login gagal/berhasil, identitas sesi, rotasi token, replay serial, logout.
- Pembatasan role dan akses Guest.
- Replay token bersamaan, diulang lima kali.
- Registrasi UMKM draft, data belum lengkap, akses pengelolaan sebelum approval.
- Upload PNG nyata, file oversize/palsu, submit, penguncian form pending.
- Revisi Admin dengan alasan dan isolasi pengajuan pemilik lain.
- Perbaikan/resubmit, persetujuan sekali, aktivasi pemilik dan warung.
- Profil/menu milik sendiri dan penolakan mutasi milik UMKM lain.
- Jam operasional, penolakan hari duplikat, fasilitas, pembayaran, foto, categoryId.
- Pencarian nama/menu, filter budget/kategori/fasilitas/pembayaran/status, radius, detail publik.
- Favorit idempotent dan terpisah antar Customer.
- Enam rating, duplikat ulasan, riwayat, dan kepemilikan ulasan.
- Balasan hanya oleh pemilik warung, rating publik, statistik.
- Laporan/moderasi, ulasan tersembunyi, penonaktifan warung, akun ditangguhkan.
